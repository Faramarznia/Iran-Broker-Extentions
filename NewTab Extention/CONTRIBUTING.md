# راهنمای مشارکت

## اصول کلی

- **بدون build/npm/CDN.** فقط HTML/CSS/JS خام. هیچ ابزار bundling اضافه نکنید مگر با تصمیم صریح تیم.
- **کد زنده منبع حقیقت است، نه مستندات.** پیش از ویرایش هر فایل در `js/`، در `newtab.html` بررسی
  کنید که فعلاً با تگ `<script src="...">` بارگذاری می‌شود (فهرست کامل فایل‌های زنده در README.md).
- هر ویژگی جدید باید از توکن‌های طراحی موجود استفاده کند (`--primary`, `--orange` `#f6a723`,
  `--surface`, `--border` و بقیهٔ متغیرهای تعریف‌شده در ابتدای `newtab.css` برای هر تم) و از هویت
  بصری تیره/آبی/کهربایی داشبورد خارج نشود.

## راه‌اندازی محیط توسعه

1. کلون کردن ریپو.
2. `chrome://extensions` → فعال‌سازی Developer mode → «Load unpacked» → انتخاب پوشهٔ `NewTab Extention`.
3. برای دیدن اثر هر تغییر، در `chrome://extensions` روی Reload افزونه بزنید (نه رفرش صفحه).

## قوانین معماری (اجباری)

- **Manifest V3 + CSP سخت‌گیرانه**: `connect-src` فقط به دامنه‌های فهرست‌شده در `manifest.json`
  اجازهٔ اتصال می‌دهد. اضافه‌کردن دامنهٔ جدید = ویرایش `manifest.json` **و** به‌روزرسانی
  `DATA-SOURCES.md` در همان تغییر.
- هیچ `inline script` یا `event handler` داخل HTML مجاز نیست (نه در `newtab.html`، نه در HTML
  تولیدشده توسط JS با `innerHTML`).
- تمام `fetch` باید با `AbortController` و timeout (پیش‌فرض ۸ ثانیه، الگوی مشترک `fetchTimeout()`
  در هر فایل) انجام شود و برای اکثر ویجت‌ها یک fallback استاتیک تعریف شود.
- state هر ویژگی فقط در `localStorage` نگه‌داری می‌شود — **هیچ `chrome.storage.*` در کد نیست و
  اضافه نکنید** مگر با دلیل مشخص (چون permission `storage` عمداً از manifest حذف شده). هیچ دادهٔ
  کاربری بدون رضایت صریح به سرور ارسال نشود.
- پشتیبانی RTL و تقویم شمسی باید در هر رابط کاربری جدید حفظ شود.
- **ریسپانسیو**: کد فعلی یک سیستم تمیز «۳ ستون بالای ۱۱۰۰px، ۲ ستون تا ۷۰۰px» ندارد — واقعیت ۸
  breakpoint متفاوت است (`560px`, `680px`, `700px`, `720px`, `760px`, `900px`/`920px`, `1080px`,
  `1099px`, و `1400px` برای گرید هاب/بنتو؛ جزئیات در `qa-reports/01-visual-regression-3-breakpoints.md`).
  برای ویژگی جدید سعی کنید از breakpointهای موجود استفاده کنید، نه افزودن یک عدد کاملاً تازه بدون
  دلیل.

## پیش از باز کردن Pull Request

- [ ] تغییر را حداقل در دو عرض متفاوت (مثلاً موبایل‌مانند زیر ۷۰۰px و دسکتاپ بالای ۱۴۰۰px) و در
      حالت RTL چک کرده‌اید.
- [ ] اگر دامنهٔ جدیدی fetch می‌شود، هم در `manifest.json` (`connect-src`/`host_permissions`) و هم
      در `DATA-SOURCES.md` اضافه شده است.
- [ ] اگر فایل جدیدی به `newtab.html` اضافه یا از آن حذف شد، README.md بخش «معماری فعلی»
      به‌روزرسانی شده است — مستندات هرگز نباید از کد عقب بیفتد.
- [ ] برای تغییرات بصری، اسکرین‌شات قبل/بعد ضمیمه شده (ابزارهای `qa-reports/tools/` را در صورت وجود
      استفاده کنید).
- [ ] هیچ کلید API یا سکرت به‌صورت hardcoded در کد commit نشده است.
