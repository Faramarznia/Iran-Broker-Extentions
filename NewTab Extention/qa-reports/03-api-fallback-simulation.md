# تست ۳: شبیه‌سازی قطعی منابع داده

**وضعیت: ⚠️ PASS جزئی — هیچ کرش/exception نشتی وجود ندارد (مهم‌ترین معیار PASS شد)، ولی یک مغایرت واقعی با ادعای PRD پیدا شد**

## نحوهٔ اجرا (واقعی، نه استنتاج از کد)

```bash
cd "NewTab Extention/qa-reports/tools"
node 03-api-fallback.js
```

اسکریپت `tools/03-api-fallback.js` با `page.setRequestInterception(true)` واقعیِ Puppeteer، برای هر سناریو یک دامنهٔ خاص را قبل از رسیدن به شبکه `abort` یا با کد `429` پاسخ می‌دهد، بعد state واقعی DOM را (نه فقط اسکرین‌شات) با `page.evaluate` می‌خواند: تعداد ردیف‌های رندرشده، متن پیام خالی/خطا، و عنوان دکمهٔ رفرش.

## جدول خلاصه (خروجی واقعی `results.json`)

| منبع | سناریو | نتیجهٔ واقعی | PASS/FAIL | فایل مربوطه |
|---|---|---|---|---|
| CoinGecko | block کامل | ✅ ۱۲ ردیف fallback استاتیک + پیام «دریافت زنده ممکن نشد — نمایش آخرین داده» | ✅ PASS | `newtab.js:934-937` (`loadCrypto` → `.catch`) |
| CoinGecko | HTTP 429 | ✅ همان رفتار بالا — 429 مثل شکست کامل مدیریت می‌شود | ✅ PASS | همان |
| Yahoo Finance (فارکس) | block کامل (هر ۹ نماد) | ⚠️ ۰ ردیف، فقط پیام «دریافت داده ممکن نشد» — **بدون fallback استاتیک** | ⚠️ **یافتهٔ جدید** (پایین) | `newtab.js:994-1019` (`loadForex`) |
| TGJU | فقط `call2` بلاک | ✅ موفق — failover به `call3` واقعاً اتفاق افتاد (۱۱ ردیف زنده، بدون پیام خطا) | ✅ PASS | `newtab.js:1030-1042` (`fetchTgju`, `TGJU_HOSTS`) |
| TGJU | هر دو میزبان بلاک | ⚠️ ۰ ردیف، فقط پیام «دریافت داده ممکن نشد» — **بدون fallback استاتیک** | ⚠️ **یافتهٔ جدید** (پایین) | همان |
| TSETMC | block کامل | ✅ موفق — تب بورس با داده‌ی پایهٔ TGJU (بدون داده‌ی تکمیلی TSETMC) کامل رندر شد، بدون خرابی | ✅ PASS | `newtab.js:1108-1140` (`fetchTsetmc`، merge با try/catch ضمنی) |

## بدون استثنای نشتی، در هیچ سناریویی

```
"pageErrorsThrown": 0   ← در هر ۶ سناریو
```

هیچ `uncaught exception`ی که اجرای بقیهٔ اسکریپت صفحه را متوقف کند مشاهده نشد — این مهم‌ترین معیار این تست بود («این باید هرگز رخ ندهد») و به‌طور قطعی PASS شد.

## ⚠️ یافتهٔ جدید نسبت به PRD: ادعای «تمام ویجت‌ها fallback استاتیک دارند» برای همهٔ منابع صادق نیست

بند ۶ PRD می‌گوید: «تمام ویجت‌ها fallback استاتیک تعریف‌شده دارند». نتایج واقعی این تست نشان داد این فقط برای **تب کریپتو** صادق است. وقتی Yahoo Finance (تب فارکس) یا هر دو میزبان TGJU (تب بازار ایران) شکست بخورند، به‌جای نمایش دادهٔ ثابت/نمونه، کاربر فقط پیام «دریافت داده ممکن نشد» و یک لیست کاملاً خالی می‌بیند — تجربهٔ کاربری ضعیف‌تر از چیزی که PRD ادعا می‌کند، هرچند بی‌خطر (بدون کرش).

**فایل/خط دقیق برای اصلاح احتمالی**: تابع `loadCrypto` در `newtab.js` (حوالی خط ۹۳۴) یک الگوی fallback خوب دارد که می‌شود در `loadForex` (خط ۹۹۴) و مسیر «هر دو TGJU شکست خورد» در `fetchTgju`/`loadIran` هم تکرار کرد.
